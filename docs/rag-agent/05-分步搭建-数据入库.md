## 步骤4：本地文件解析（MVP）

**状态**：⬜  

1. PDF / Word / TXT / Markdown 文本提取  
2. 清洗：多余空白、页眉页脚噪声、异常控制字符  
3. 元数据：文件名、来源、`content_hash`、创建时间  

**验收勾选**
- [ ] 样例 PDF、Word、Markdown 均可抽出可读正文
- [ ] 清洗后无明显乱码/重复页眉

## 步骤5：网站爬取（完整版）

**状态**：⬜  

1. 单页：URL → 正文 → 去 HTML  
2. 批量：间隔、UA、重试；可选深度爬取（限域名/深度）  
3. **合规**：robots.txt、版权与隐私，仅爬授权范围（见 [10-安全合规.md](./10-安全合规.md)）  

**验收勾选**
- [ ] 单 URL 入库成功
- [ ] 失败重试与超时行为符合预期
- [ ] 已确认爬取授权范围

---

## 步骤6：业务数据库同步（完整版）

**状态**：⬜  

1. 连接配置 + 字段映射（哪些拼文本、哪些进 meta）  
2. 增量：按 `updated_at`；支持手动/定时触发  
3. 行 → 结构化文本 → 清洗 → 进入统一 Pipeline  

**验收勾选**
- [ ] 全量同步成功
- [ ] 增量只拉取变更行
- [ ] 映射配置可文档化复用

---

## 步骤7：切片、向量化与异步入库

**状态**：⬜  

1. **切片策略（命名勿混淆）**
   - MVP 默认：**固定窗口切片**（`chunk_size` + `chunk_overlap`）
   - 可选：按 Markdown 标题/段落边界切；真·语义切片另立方案  
2. 批量 Embedding，控制并发与限流  
3. 一致性：同 `doc_id` **先删旧 chunk（关系库+向量库）再写入新版本**  
4. 统一入口：`ingest_pipeline(kb_id, source_type, source_data)`；HTTP 只创建 `ingest_task`，Worker 执行  
5. 失败可重试；`content_hash` 未变可跳过  

**验收勾选**
- [ ] Worker 能消费 queued 任务并更新进度
- [ ] 检索能命中新入库文档
- [ ] 重复上传相同内容不产生重复有效 chunk（或明确跳过）
