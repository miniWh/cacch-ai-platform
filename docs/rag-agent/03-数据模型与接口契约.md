## 1. 实体关系（逻辑）

```text
knowledge_base 1 ── N document 1 ── N chunk
session 1 ── N message
message 1 ── N message_citation（关联 chunk）
ingest_task N ── 1 document / knowledge_base
```

## 3. 向量库集合约定

- Collection/表名建议：`kb_chunk_{embedding_dim}` 或按 kb 分集合  
- 字段：`chunk_id`, `kb_id`, `doc_id`, `vector[dim]`, `content`（可选）  
- 度量：默认 **COSINE**（与 Embedding 归一化策略一致）  
- **更换 Embedding 模型或维度 = 全量重建向量，禁止混写**

- [ ] 索引类型与基础参数已记录（如 HNSW/IVF）

## 4. 接口契约

> 路径可用扁平写法（如下）或统一加前缀 `/api/v1/rag`，与助手/Agent 等域隔离。平台网关按前缀路由即可。

### 4.1 统一响应（非流式）

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

错误：`code != 0`，`message` 为可读原因。

### 4.2 对话（非流式）`POST /api/v1/chat`

请求：
```json
{
  "session_id": "可选，空则新建",
  "kb_id": 1,
  "query": "报销流程是什么？",
  "stream": false,
  "top_k": 4
}
```

响应 `data`：
```json
{
  "session_id": "s_xxx",
  "answer": "根据知识库……",
  "citations": [
    {
      "chunk_id": "c_1",
      "doc_id": 12,
      "title": "报销制度.pdf",
      "score": 0.83,
      "snippet": "……报销需先提交……"
    }
  ]
}
```

### 4.3 对话（流式）

`POST /api/v1/chat`（`stream: true`）或 `POST /api/v1/chat/stream`  
`Content-Type: text/event-stream`

```text
event: meta
data: {"session_id":"s_xxx"}

event: token
data: {"text":"根据"}

event: citations
data: {"citations":[...]}

event: done
data: {"finish_reason":"stop"}

event: error
data: {"message":"模型调用失败，请稍后重试"}
```

### 4.4 知识库与入库

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| POST | `/api/v1/kb` | 创建知识库 |
| GET | `/api/v1/kb` | 列表 |
| POST | `/api/v1/kb/{kb_id}/documents/upload` | 上传文件 → ingest_task |
| POST | `/api/v1/kb/{kb_id}/documents/url` | 提交 URL |
| POST | `/api/v1/kb/{kb_id}/sync/db` | 触发库表同步 |
| GET | `/api/v1/ingest/tasks/{task_id}` | 查询入库进度 |
| GET | `/api/v1/sessions` | 会话列表 |
| GET | `/api/v1/sessions/{id}` | 会话详情 |
| DELETE | `/api/v1/sessions/{id}` | 删除会话 |
| GET | `/api/v1/health` | 健康检查 |

鉴权（MVP）：请求头 `Authorization: Bearer <API_AUTH_TOKEN>`。
