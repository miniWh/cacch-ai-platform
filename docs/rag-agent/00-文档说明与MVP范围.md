## 1. 读者与目标

面向在 **CACCH AI Platform** 上落地 **检索增强（RAG）知识问答** 的后端/全栈工程师。

本域交付闭环：**多源知识入库 → 语义检索 → 大模型问答 → Web 对话（含引用来源）**。

平台整体目标（多 AI 能力）见 [文档中心](../README.md)，本文不覆盖全部平台范围。

## 2. 边界说明

### 2.1 本域覆盖

**RAG 知识问答**：以内部知识库为依据的问答，强调召回与引用溯源。

### 2.2 不属于本域（请改走其他文档）

| 需求类型 | 去向 |
| :--- | :--- |
| 无知识库/弱知识库多轮助手 | [chat-assistant](../chat-assistant/README.md) |
| 工具调用、多步办事 | [agent-orchestration](../agent-orchestration/README.md) |
| 文案/报告/摘要生成中台 | [content-generation](../content-generation/README.md) |
| 字段抽取、分类、结构化输出 | [doc-intelligence](../doc-intelligence/README.md) |

可与本域 **组合**（例如 Agent 把检索当工具），但文档与迭代 backlog 应分域管理。

## 3. MVP 与完整版（本域）

| 范围 | 包含能力 | 建议工期（参考） |
| :--- | :--- | :--- |
| **MVP** | 本地文件入库、单知识库检索问答、多轮对话、SSE 流式、引用来源、基础会话历史 | 1.5～3 周 |
| **完整版** | + 网站爬取、业务库同步、知识库管理页、增量更新、异步入库任务、评测与调优 | 再 +2～4 周 |

### MVP 验收标准（必须全部通过）

1. 上传 PDF/Word/TXT/Markdown，入库成功且可在管理接口查询文档状态  
2. 基于该知识库提问，能召回相关片段并生成回答  
3. 回答下方能展示引用来源（文件名/页码或 chunk 摘要）  
4. 支持 SSE 流式输出与至少 3 轮上下文记忆  
5. 空检索、模型超时有明确兜底文案，不白屏/不裸报错  

## 4. 本域目标与能力

### 核心目标

**多源数据采集 → 清洗切片 → 向量存储 → 语义检索 → 大模型问答 → 前端交互**

用户通过 Web 对话页，基于指定内部知识库提问，并溯源到具体文档片段。

### 覆盖能力

- **多源数据接入**：本地文档（MVP）、网站爬取、业务库同步（完整版）
- **向量知识库**：切片、向量化、异步入库、增量更新、版本与删除一致性
- **智能问答**：语义召回（可选多路+重排）、上下文拼接、流式生成、对话记忆、引用
- **Web**：对话、流式展示、引用、知识库管理（完整版）

### 非目标（本域不做）

- 作为平台唯一产品形态（平台还有其他 AI 能力域）  
- Function Calling / 多 Agent 协作主路径（见 Agent 域）  
- 多租户计费、复杂权限（仅预留 `user_id` / `kb_id`）  
- 图片 OCR、知识图谱（演进或文档智能域）  

## 5. 仓库与命名

- 平台仓库：`cacch-ai-platform`  
- 本域可为平台内模块，或独立服务 `cacch-ai-rag-service`  
- 源码根包：`app/`；发布包名可用 `cacch_ai_xxx`  
- API 前缀（已选定）：本域 `/api/v1/rag/...`；终端对话 `/api/v1/apps/{id}/chat`  
- LLM/鉴权/任务：**复用平台共享底座**，见 [共享基础能力](../platform/01-共享基础能力.md)
