## 1. 背景与目标

### 1.1 背景

业务侧维护了一批国内外农药相关「资料查询网站」清单，用于查询：

1. **有效成分在各国登记情况**  
2. **有效成分在各国登记评审资料**（评审报告、出版物、标准等）

现状依赖人工打开各官网检索，效率低、难沉淀、难追溯。希望通过平台能力：从授权网址采集/导入资料，再以 **AI 对话** 方式检索相关信息，并给出可核验来源。

### 1.2 一句话目标

用户用自然语言询问某有效成分在某国/地区的登记或评审信息 → 系统基于已入库资料（及可选实时站点查询）生成回答 → **必须附引用来源（站点 / URL / 文档）**。

### 1.3 成功标准（业务）

| # | 标准 | 阶段 |
| :---: | :--- | :---: |
| 1 | 已创建并发布本业务 App（`rag_chat`），bindings 指向目标 kb | P0 |
| 2 | 管理员仅在页面增删改站点清单，并探活 / 启停（无文件导入） | P0 |
| 3 | 经该 App 对话可问答，回答含 citations | P0 |
| 4 | 对约定样例物质（≥5 个）能命中已入库评审/登记相关片段 | P0 |
| 5 | 至少 2 个高价值站点可自动/半自动同步入库 | P1 |
| 6 | 终端对话切换为统一 `POST /api/v1/apps/{id}/chat` | P1 |
| 7 | 无证据时明确拒答或提示人工上官网复核，不编造登记结论 | P0～P2 |

## 2. 需求归类与边界

### 2.1 能力归类（平台）

| 判断 | 结论 |
| :--- | :--- |
| 必须依据权威资料且可溯源 | **RAG 知识问答**（主路径） |
| 部分库仅支持按物质名实时检索 | **Agent 工具调用**（P2 增强） |
| 从报告中抽登记状态字段 | **文档智能**（P3，可选） |

本需求：

1. **能力域**：RAG（检索、入库、引用）+ 可选 P2 Agent 工具  
2. **产品粘合层**：落地为平台 **App**（见 [应用与能力挂载模型](../../platform/02-应用与能力挂载模型.md)），禁止做成与平台工作台脱节的独立门户  
3. **复用**：LLM 网关（`model_profile`）、鉴权、异步任务、观测  

实施步骤对齐：[../README.md](../README.md)；入库见 [../05-分步搭建-数据入库.md](../05-分步搭建-数据入库.md)；安全见 [../10-安全合规.md](../10-安全合规.md)。

### 2.2 范围内（In Scope）

- 创建并配置本业务 App：`app_type=rag_chat`，含 `model_profile_id`、`bindings_json`  
- 平台工作台内：按 App 进入对话；管理页挂载站点清单 / 文档 / 任务（可为本 App 专属功能页）  
- 站点清单 **仅** 通过管理页 CRUD 维护  
- 多策略采集：知识文档上传、单 URL、列表收获、站点连接器  
- 统一入库 Pipeline：清洗 → 切片 → Embedding → 向量/元数据落库  
- Web 对话：多轮、SSE、引用溯源、会话历史（入口见 §6.3）  
- 异步任务进度查询、失败原因可见  
- 域名白名单、限速、robots/授权合规检查清单  

### 2.3 范围外（Out of Scope）

| 不做 | 说明 |
| :--- | :--- |
| Word / docx / CSV / YAML 维护或导入站点清单 | 站点清单只走管理页；附录 A 仅需求参考 |
| 整站无差别深度爬虫 | 清单站点多为检索门户，盲爬首页无业务价值 |
| 绕过登录/验证码/付费墙 | 无授权则改知识文档上传或官方开放数据 |
| 替代官方登记系统出具法律效力结论 | 系统仅辅助检索；关键结论需人工复核 |
| 首期做完整多租户计费 | 字段可预留 |
| 首期全量 Agent 任意 HTTP 工具 | 须白名单连接器（见平台 05） |
| 脱离 App 粘合层的独立「问答站」孤岛 | 前端可先做业务页，但必须挂在 App 下，对话入口按 §6.3 演进 |

### 2.4 关键假设

- 业务可提供/确认可公开访问的报告样本与样例有效成分中英文名  
- 部署环境可访问目标外网域名（或提供代理策略）  
- Embedding 模型与维度在 P0 前选定且不再随意更换  
- 平台 App 表 / 统一对话路由按 [02](../../platform/02-应用与能力挂载模型.md) 可落地（P0 至少一张 App 配置表）

### 2.5 产品形态：平台 App + 工作台功能页

本业务 **不是** 域外独立门户，而是平台上的一个 App 实例。站点清单不提供任何文件型维护通道；权威数据在 DB，由管理页读写。

| 层级 | 对象 | 说明 |
| :--- | :--- | :--- |
| 产品 | App「农药登记评审资料问答」（名称可调） | `app_type=rag_chat` |
| 能力 | RAG 对话 + 本域站点/文档管理 | 检索/生成走 RAG；站点清单为本业务扩展 |
| 资源绑定 | `bindings_json` | 指向 kb、prompt、检索参数；站点清单归属该 kb |
| 模型 | `model_profile_id` | 引用网关侧模型配置（平台 03） |
| 入口 | `entrypoints: [web, api]` | Web 工作台对话；API 同 App 对话入口 |

**App 挂载样例（P0 必写进配置/种子数据）**

```text
name: 农药登记评审资料问答
app_type: rag_chat
status: published
model_profile_id: default_chat          # 按环境实际 profile
bindings_json:
  kb_ids: [<本业务知识库 id>]
  prompt_id: "rag_pesticide_sources"    # 或先用 rag_default，再特化
  retrieve: { top_k: 4, hybrid: false }
  # 站点清单不另建 App；归属上述 kb，经域 API 管理
entrypoints: [web, api]
```

| 方式 | 定位 | 说明 |
| :--- | :--- | :--- |
| **页面维护站点** | 站点清单唯一入口 | 管理员增删改、探活、启停、同步 |
| **附录 A** | 需求参考 | 首配对照录入；非系统功能、不可上传 |

> 知识库仍可上传 PDF/Word 等 **资料正文**（F-ING-01），与「站点清单」无关。

**信息架构（对齐平台工作台，见 02 §4）**

```text
平台工作台
├── 应用列表 / 应用配置     ← 本业务 App 的创建、发布、bindings、model_profile
├── 对话台                  ← 按 App 进入会话（研究员）
└── 本 App 挂载功能页
    ├── 站点清单            ← P0（唯一维护入口）
    ├── 文档与上传          ← P0 API / P0～P1 页
    ├── 入库任务            ← P0 API / P1 页
    └── 知识库设置          ← P1（可复用平台知识库管理）
```

P0 若工作台壳未齐：允许「本 App 专用前端」先交付对话 + 站点页，但 **必须** 已持久化 App 记录与 bindings，且前端路由/配置以 `app_id` 为上下文，避免写死「无 App 的裸 kb 聊天页」成为终态。

**角色权限（最低）**

| 角色 | 对话台 | 站点清单 | 文档/任务 | App 配置 |
| :--- | :---: | :---: | :---: | :---: |
| 研究员 viewer | 读/问 | 只读（可选） | 只读 | 无 |
| 管理员 editor | 读/问 | 增删改/探活/同步 | 上传与查看任务 | 只读或有限编辑 bindings |
| 系统 admin | 全部 | 全部 | 全部 | 全部 |

P0 若暂无完整 RBAC：可用同一 Bearer Token + 管理路由前端隐藏；P1 再拆角色。

## 3. 用户与典型场景

### 3.1 用户角色

| 角色 | 诉求 |
| :--- | :--- |
| 业务研究员 | 快速查某有效成分登记/评审线索，并打开原文核对 |
| 知识库管理员 | 维护种子站、触发同步、查看失败任务、导入 PDF |
| 系统管理员 | 合规、限流、密钥与部署 |

### 3.2 典型问法（验收用例素材）

1. 「草甘膦在欧盟的登记/评审资料有哪些？」  
2. 「某有效成分在美国 EPA / PPIS 相关信息从哪些页面可以查？」  
3. 「日本评价书里关于某某物质的环境归趋结论摘要是什么？（基于已入库文本）」  
4. 「GB/T 相关农药标准在国标平台上的检索入口是什么？」  
5. 「库里没有某某物质时请直接说明，并给出建议官网。」  

> 业务需在开工前锁定 **≥5 个样例物质**（含中英别名，尽量含 CAS），作为 P0 黄金问法。

### 4.2 数据采集与入库

**优先级**：P0 人工导入；P1 自动同步  

| ID | 需求 | 阶段 | 验收 |
| :--- | :--- | :---: | :--- |
| F-ING-01 | 支持本地 PDF/Word/TXT/Markdown 上传入库 | P0 | 任务 success，chunk 可检索 |
| F-ING-02 | 支持提交单个 URL 入库（正文抽取或附件下载） | P0/P1 | 与现有 `documents/url` 契约对齐 |
| F-ING-03 | 入库一律异步：`ingest_task`，HTTP 只返回 `task_id` | P0 | 不阻塞等待向量化 |
| F-ING-04 | `content_hash` 未变化可跳过；同 doc 重入先删旧 chunk 再写 | P0 | 无重复有效向量垃圾 |
| F-ING-05 | 列表收获（list_harvest）：发现报告列表 → 下载 PDF/HTML → Pipeline | P1 | ≥1 站跑通 |
| F-ING-06 | 站点连接器（connector）：按物质名/关键词查询 → 结果页或报告入库 | P1 | ≥2 站跑通 |
| F-ING-07 | 定时/手动触发站点同步；进度与失败原因可查 | P1 | 管理页或 API 可见 |
| F-ING-08 | 仅允许白名单域名出站请求 | P0 | 非白名单拒绝并记日志 |

**采集模式定义**

| crawl_mode | 含义 | 适用 |
| :--- | :--- | :--- |
| `manual` | 人工下载后上传 | 登录墙、不稳定站、首期 |
| `single_page` | 单 URL 抽正文 | 静态说明页 |
| `list_harvest` | 列表发现 + 详情/PDF | 出版物、评价书列表 |
| `connector` | 站点专用适配器（检索表单/已知 API） | PPIS、EFSA RoQ、标准库等 |

## 5. 非功能需求

| ID | 类别 | 要求 |
| :--- | :--- | :--- |
| NFR-01 | 性能 | 单次对话首 token（已有检索上下文）P95 ＜ 5s（视模型 SLA，可调整） |
| NFR-02 | 性能 | 单文档（≤50 页 PDF）入库任务在 Worker 正常时 10 分钟内完成（环境基线需实测校准） |
| NFR-03 | 可靠 | 入库失败可重试；任务状态 `queued/running/success/failed` |
| NFR-04 | 安全 | Bearer Token / 平台统一鉴权；出站域名白名单；审计日志含 user、kb、url |
| NFR-05 | 合规 | 遵守 robots 与版权；仅抓授权范围；原文留存策略由业务确认 |
| NFR-06 | 可运维 | 结构化日志；Token/调用量可统计；任务失败原因可读 |
| NFR-07 | 限流 | 每站点独立 `rate_limit`（默认建议 ≤1 req/2s，可配置） |

## 6. 数据与契约要点

### 6.1 种子站点（建议表 `source_site` 或等价配置）

| 字段 | 说明 | 必填 |
| :--- | :--- | :---: |
| site_id | 稳定主键，如 `us_ppis` | 是 |
| name | 展示名 | 是 |
| region | US / EU / UK / AU / JP / CN / INT | 是 |
| category | registration / evaluation / standard / database | 是 |
| entry_url | 入口 URL | 条件 |
| crawl_mode | manual / single_page / list_harvest / connector | 是 |
| allowed_domains | JSON 数组 | 是 |
| rate_limit_qps | 小数或间隔秒 | 否 |
| status | active / broken / pending_url / disabled | 是 |
| notes | 备注（笔误、需日文名等） | 否 |
| last_probe_at / last_probe_status | 探活 | 否 |

文档实体沿用 RAG 域 `document`：`source_type=web|file`，`source_uri`，`meta_json` 建议含：

```json
{
  "site_id": "eu_efsa_publications",
  "region": "EU",
  "doc_type": "evaluation_report",
  "substance_hints": ["glyphosate"],
  "fetched_at": "2026-08-08T00:00:00Z",
  "acl": {}
}
```

### 6.2 知识组织建议（逻辑模型）

不以「网站首页」为知识单元，而以 **有效成分相关资料片段** 为检索单元：

```text
ActiveIngredient（逻辑实体，P1 可先用 meta/别名词典近似）
  ├── aliases / cas
  ├── RegistrationRecord（可先以 chunk + meta 表达）
  ├── EvaluationDoc
  └── StandardRef
```

P0 可不建独立物质主数据表；P1 建议增加别名词典表（中/英/日名、CAS → 标准名）。

### 6.3 API（App 粘合层 + RAG 域扩展）

对齐 [平台 02 §5](../../platform/02-应用与能力挂载模型.md)：**终端用户优先走 App 入口**；域 API 保留供管理与调试。

#### 6.3.1 App 粘合层（平台）

| 方法 | 路径 | 说明 | 阶段 |
| :--- | :--- | :--- | :---: |
| GET/POST | `/api/v1/apps` | 应用 CRUD | P0 |
| GET | `/api/v1/apps/{id}` | 含 `app_type`、`model_profile_id`、`bindings_json` | P0 |
| GET | `/api/v1/apps/{id}/config` | 前端拉配置 | P0/P1 |
| POST | `/api/v1/apps/{id}/chat` | **统一对话入口**（按 `app_type` 路由到 RAG） | **P1 终端默认**；P0 可先实现壳或内部转发 |

#### 6.3.2 对话入口演进

| 阶段 | 前端对话调用 | 说明 |
| :--- | :--- | :--- |
| P0 | 可暂用域内 `POST /api/v1/chat` 或 `/api/v1/rag/.../chat`（以 03 为准） | 请求须带或可解析出 `app_id`；kb 来自该 App 的 bindings，禁止永久写死无 App 上下文 |

#### 6.3.3 RAG 域 API（管理 / 入库；可与 App 并存）

| 方法 | 路径 | 说明 | 阶段 |
| :--- | :--- | :--- | :---: |
| POST | `/api/v1/kb` | 创建知识库 | P0 |
| POST | `/api/v1/kb/{kb_id}/documents/upload` | 文件入库 | P0 |
| POST | `/api/v1/kb/{kb_id}/documents/url` | 单 URL 入库 | P0/P1 |
| GET | `/api/v1/ingest/tasks/{task_id}` | 任务进度 | P0 |
| GET | `/api/v1/kb/{kb_id}/sources` | 站点列表 | P0 |
| POST | `/api/v1/kb/{kb_id}/sources` | 新建站点 | P0 |
| GET | `/api/v1/kb/{kb_id}/sources/{site_id}` | 站点详情 | P0 |

| 风险 | 等级 | 对策 |
