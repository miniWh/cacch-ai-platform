## 1. 背景与目标

### 1.1 背景

业务侧维护了一批国内外农药相关「资料查询网站」清单，用于查询：

1. **有效成分在各国登记情况**  
2. **有效成分在各国登记评审资料**（评审报告、出版物、标准等）

现状依赖人工打开各官网检索，效率低、难沉淀、难追溯。希望通过平台能力：从授权网址采集/导入资料，再以 **AI 对话** 方式检索相关信息，并给出可核验来源。

### 1.2 一句话目标

用户用自然语言询问某有效成分在某国/地区的登记或评审信息 → 系统基于已入库资料（及可选实时站点查询）生成回答 → **必须附引用来源（站点 / URL / 文档）**。

### 1.3 成功标准（业务）

| # | 标准 | 阶段 |
| :---: | :--- | :---: |
| 1 | 种子清单可导入、可探活、可维护 | P0 |
| 2 | 至少 1 个知识库可对话问答，回答含 citations | P0 |
| 3 | 对约定样例物质（≥5 个）能命中已入库评审/登记相关片段 | P0 |
| 4 | 至少 2 个高价值站点可自动/半自动同步入库 | P1 |
| 5 | 无证据时明确拒答或提示人工上官网复核，不编造登记结论 | P0～P2 |

## 2. 需求归类与边界

### 2.1 能力归类（平台）

| 判断 | 结论 |
| :--- | :--- |
| 必须依据权威资料且可溯源 | **RAG 知识问答**（主路径） |
| 部分库仅支持按物质名实时检索 | **Agent 工具调用**（P2 增强） |
| 从报告中抽登记状态字段 | **文档智能**（P3，可选） |

本需求挂载于 RAG 能力域，复用平台：LLM 网关、鉴权、异步任务、观测。  
实施步骤对齐：[../README.md](../README.md)；入库见 [../05-分步搭建-数据入库.md](../05-分步搭建-数据入库.md)；安全见 [../10-安全合规.md](../10-安全合规.md)。

### 2.2 范围内（In Scope）

- 将网址清单结构化为「种子站点目录」并支持管理  
- 多策略采集：人工/半自动导入、列表收获、站点连接器  
- 统一入库 Pipeline：清洗 → 切片 → Embedding → 向量/元数据落库  
- Web 对话：多轮、SSE、引用溯源、会话历史  
- 异步任务进度查询、失败原因可见  
- 域名白名单、限速、robots/授权合规检查清单  

### 2.3 范围外（Out of Scope）

| 不做 | 说明 |
| :--- | :--- |
| 整站无差别深度爬虫 | 清单站点多为检索门户，盲爬首页无业务价值 |
| 绕过登录/验证码/付费墙 | 无授权则改人工导入或官方开放数据 |
| 替代官方登记系统出具法律效力结论 | 系统仅辅助检索；关键结论需人工复核 |
| 首期做完整多租户计费 | 字段可预留 |
| 首期全量 Agent 任意 HTTP 工具 | 须白名单连接器（见平台 05） |

### 2.4 关键假设

- 业务可提供/确认可公开访问的报告样本与样例有效成分中英文名  
- 部署环境可访问目标外网域名（或提供代理策略）  
- Embedding 模型与维度在 P0 前选定且不再随意更换

## 3. 用户与典型场景

### 3.1 用户角色

| 角色 | 诉求 |
| :--- | :--- |
| 业务研究员 | 快速查某有效成分登记/评审线索，并打开原文核对 |
| 知识库管理员 | 维护种子站、触发同步、查看失败任务、导入 PDF |
| 系统管理员 | 合规、限流、密钥与部署 |

### 3.2 典型问法（验收用例素材）

1. 「草甘膦在欧盟的登记/评审资料有哪些？」  
2. 「某有效成分在美国 EPA / PPIS 相关信息从哪些页面可以查？」  
3. 「日本评价书里关于某某物质的环境归趋结论摘要是什么？（基于已入库文本）」  
4. 「GB/T 相关农药标准在国标平台上的检索入口是什么？」  
5. 「库里没有某某物质时请直接说明，并给出建议官网。」  

> 业务需在开工前锁定 **≥5 个样例物质**（含中英别名，尽量含 CAS），作为 P0 黄金问法。

## 6. 数据与契约要点

### 6.1 种子站点（建议表 `source_site` 或等价配置）

| 字段 | 说明 | 必填 |
| :--- | :--- | :---: |
| site_id | 稳定主键，如 `us_ppis` | 是 |
| name | 展示名 | 是 |
| region | US / EU / UK / AU / JP / CN / INT | 是 |
| category | registration / evaluation / standard / database | 是 |
| entry_url | 入口 URL | 条件 |
| crawl_mode | manual / single_page / list_harvest / connector | 是 |
| allowed_domains | JSON 数组 | 是 |
| rate_limit_qps | 小数或间隔秒 | 否 |
| status | active / broken / pending_url / disabled | 是 |
| notes | 备注（笔误、需日文名等） | 否 |
| last_probe_at / last_probe_status | 探活 | 否 |

文档实体沿用 RAG 域 `document`：`source_type=web|file`，`source_uri`，`meta_json` 建议含：

```json
{
  "site_id": "eu_efsa_publications",
  "region": "EU",
  "doc_type": "evaluation_report",
  "substance_hints": ["glyphosate"],
  "fetched_at": "2026-08-08T00:00:00Z",
  "acl": {}
}
```

### 6.2 知识组织建议（逻辑模型）

不以「网站首页」为知识单元，而以 **有效成分相关资料片段** 为检索单元：

```text
ActiveIngredient（逻辑实体，P1 可先用 meta/别名词典近似）
  ├── aliases / cas
  ├── RegistrationRecord（可先以 chunk + meta 表达）
  ├── EvaluationDoc
  └── StandardRef
```

P0 可不建独立物质主数据表；P1 建议增加别名词典表（中/英/日名、CAS → 标准名）。

## 9. 交互与 Prompt 基线

### 9.1 回答结构（建议）

1. 直接结论（仅在有检索依据时）  
2. 分点说明（国家 / 资料类型 / 关键信息）  
3. 引用来源列表  
4. 必要时：官网复核提示  

### 9.2 系统约束（必须写入 Prompt）

- 只使用检索到的上下文与工具返回；禁止编造登记号、批准状态、毒性结论  
- 上下文不足时明确「未在知识库命中」  
- 声明：本系统为资料检索辅助，不构成法规符合性认定  

模板可沉淀至 [../appendix/C-Prompt与代码示例.md](../appendix/C-Prompt与代码示例.md)。

## 10. 合规与风险

| 风险 | 等级 | 对策 |
| :--- | :---: | :--- |
| 动态站/验证码导致自动采集失败 | 高 | 连接器小步试点；其余 manual |
| URL 失效、笔误（如 `.heml`） | 中 | P0 探活；种子表可修 |
| 版权与 robots 限制 | 高 | 白名单 + 业务书面授权范围 |
| 模型幻觉导致错误登记结论 | 高 | 强制引用 + 拒答策略 + 人工复核提示 |
| 多语言别名不一致 | 中 | 别名词典；提问改写扩展检索词 |
| 外网不稳定 | 中 | 重试、超时、任务可恢复 |

合规勾选（上线前）：

- [ ] 可抓取域名清单已签字确认  
- [ ] 原文是否落对象存储已确认  
- [ ] robots/版权评估完成（见 [../10-安全合规.md](../10-安全合规.md)）
