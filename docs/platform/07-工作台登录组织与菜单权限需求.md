## 1. 背景与目标

当前工作台使用环境变量固定 `Bearer API_AUTH_TOKEN`，无真实用户登录；侧栏菜单为本地 `localStorage` 配置，无法按人授权。

本期目标：建立**组织树 + 账号（挂靠组织）+ 登录/强制改密 + 角色模板与菜单权限**，并为后续**企业微信入口 / SSO**预留用户 ID（即企微 UserId = HR `staffNo`）。

### 1.1 明确决策（已确认）

| 议题 | 决策 |
| :--- | :--- |
| 自助注册 | **禁止**；仅登录 |
| 开户 | 仅管理员；`persondetail` **查不到一律禁止开户** |
| 手机号 | **不限大陆号**；开户时手机号从 `persondetail` 按库内值选用/校验，库中不存在则不可开户 |
| 用户 ID | 同步 `persondetail.staffNo`；**目的是后续企微功能入口与 SSO**，该 ID 即企微用户 ID |
| 组织 | **必须**挂在组织树某节点下，不允许无组织账号 |
| 权限粒度 | **仅到菜单**；不做菜单级以下（按钮/数据行）控制 |
| 角色 | **本期上角色模板**（模板含默认菜单集，开户可套用后再微调） |
| HR 刷新 | **不提供**姓名/邮箱/在职等从 HR 再次刷新的功能；以开户当时回填为准（在职状态用于开户/登录校验规则见下文） |
| 密码交付 | 随机/设定密码后**弹窗提示用户自行保存**（仅展示一次） |
| 登录便利 | 登录页提供**今日免登录** |
| HTTPS | 当前内网**暂不开启**；需求中其余安全项全部要做 |
| Token | **用户 Token 与现有后端 `API_AUTH_TOKEN` 同步改造**（见 §8） |

| 编号 | 需求 | 说明 |
| :--- | :--- | :--- |
| O-01 | 组织树存在 | 平台维护组织节点树（根 → 部门/组等），供账号挂靠 |
| O-02 | 账号必挂组织 | 每个账号**必须**归属且仅归属一个组织节点（若需兼职，本期不做多组织） |

## 4. 账号与 HR 主数据

### 4.1 开户流程

1. 管理员进入「账号管理」→ 新增。  
2. 选择**组织节点**（必填）。  
3. 输入或选择**手机号**：该手机号必须在 PG **`persondetail.mobileNo`** 中存在；**不存在则禁止开户**（不支持任何形式的「空号注册」）。  
4. 系统只读查询 `persondetail`，回填并落库：  

| 平台字段 | HR 来源 | 说明 |
| :--- | :--- | :--- |
| 用户 ID（`staff_no` / 对外 user id） | `staffNo` | **企微用户 ID**；后续 SSO 跳转主键 |
| 手机号 | `mobileNo` | 国际/国内均可能；以表内值为准，不做「仅 11 位大陆号」限制 |
| 姓名 | `staffName` | 开户时写入 |
| 邮箱 | `workEmail` | 可空则允许空 |
| 在职状态 | `staffStatus` | 见 §4.2 |

5. 设置密码：支持手工输入或**自动生成随机密码**。  
6. 选择**角色模板**（带出默认菜单），可再勾选调整菜单（仅到菜单）。  
7. 保存后 `must_change_password = true`。  
8. **密码交付**：弹窗展示密码明文（可复制），文案明确要求**用户自行保存**；关闭后不可再次查看明文。

### 4.2 在职状态

| 编号 | 需求 | 说明 |
| :--- | :--- | :--- |
| U-S01 | 字段 | 账号表冗余保存开户时的 `staff_status`（来自 `persondetail.staffStatus`） |
| U-S02 | 在职取值 | 值为 **`IN_SERVICE`** 视为在职 |
| U-S03 | 开户 | 非 `IN_SERVICE` **禁止开户**（与查不到同样拒绝） |
| U-S04 | 登录 | 登录时若账号表标记非在职，或实现上选择再次读 HR 校验为非 `IN_SERVICE`，则拒绝登录；**本期不提供管理端「从 HR 刷新」按钮**——若需更新在职状态，由管理员停用账号或后续另立同步任务（非本需求页面能力） |

> 说明：不提供 HR 刷新功能；在职字段以开户写入 + 管理员停用为主。若登录需强一致，可在登录接口**只读**查一次 `persondetail.staffStatus`（不算「刷新功能」），推荐纳入实现以防离职仍能登；需求默认：**登录时只读校验 HR 在职状态，失败则拒绝**。

### 4.3 账号主数据（平台表必要字段）

| 字段 | 必填 | 说明 |
| :--- | :---: | :--- |
| 主键 | 是 | 库内自增/UUID |
| `staff_no`（用户 ID） | 是 | = `staffNo` = 企微 UserId |
| `mobile` | 是 | = `mobileNo`，唯一 |
| `name` | 是 | = `staffName` |
| `email` | 否 | = `workEmail` |
| `staff_status` | 是 | 开户时自 HR；在职为 `IN_SERVICE` |
| `org_id` | 是 | 所属组织节点 |
| `password_hash` | 是 | 仅哈希 |
| `must_change_password` | 是 | 开户/管理员重置后为 true |
| `status` | 是 | active / disabled |
| 角色与菜单关联 | 是 | 见 §6 |
| `created_at` / `updated_at` / `last_login_at` | 是 | 系统维护 |
| `created_by` | 建议 | 开户人 |
| `password_changed_at` | 建议 | 审计 |
| `remark` | 否 | 备注 |

- 手机号唯一；`staff_no` 唯一。  
- `persondetail` **只读**；平台账号写操作仅限 `cacch_ai_*`。

### 4.4 账号管理其他能力

| 编号 | 需求 |
| :--- | :--- |
| U-01 | 列表：手机号/姓名/用户 ID/组织/角色/状态/在职筛选 |
| U-02 | 停用/启用；停用后不可登录，已发 Token 失效 |
| U-03 | 重置密码（可随机生成）→ 强制改密 + 交付弹窗 |
| U-04 | 调整组织、角色、菜单（仅管理员且自身有对应管理菜单权限） |
| U-05 | 禁止自助注册接口与前端入口 |

## 5. 登录、会话与强制改密

### 5.1 登录

| 编号 | 需求 | 说明 |
| :--- | :--- | :--- |
| A-01 | 仅登录 | 登录页无注册入口 |
| A-02 | 凭证 | 手机号 + 密码（手机号格式随国际号，前端做宽松校验即可） |
| A-03 | 失败提示 | 统一「账号或密码错误」类文案，避免枚举用户是否存在 |
| A-04 | 今日免登录 | 勾选后，在**当日剩余时间内**（建议按应用时区 Asia/Shanghai 的自然日 23:59:59 截止，或「自登录起 24h 内且不超过当日」——**推荐：自然日当日有效**）免重复输入；关闭浏览器仍保持（需持久化 Token/Refresh）；次日需重新登录 |
| A-05 | 未勾选 | 使用较短会话（如关闭浏览器失效或短 TTL），具体 TTL 实现阶段定，须短于「今日免登录」 |
| A-06 | 路由守卫 | 未登录访问业务页 → 登录页，支持 `redirect` 回跳 |
| A-07 | 登出 | 清除会话；今日免登录一并失效 |

### 5.2 强制改密

| 编号 | 需求 |
| :--- | :--- |
| P-01 | `must_change_password=true` 时仅允许改密页与登出 |
| P-02 | 未改密禁止进入工作台及一切业务 API |
| P-03 | 新密码满足复杂度；不得与旧密码相同 |
| P-04 | 改密成功后清除标记，进入默认有权首页 |
| P-05 | 管理员重置密码后再次强制改密 |

### 5.3 密码交付弹窗

- 开户成功、重置密码成功：模态框展示密码。  
- 文案须提示：**请立即复制并自行妥善保存；关闭后无法再次查看。**  
- 提供一键复制；确认关闭后不再返回明文。

## 6. 角色模板与菜单权限

### 6.1 菜单

| 编号 | 需求 |
| :--- | :--- |
| M-01 | 系统菜单目录：id、名称、路由、图标、排序、是否可授权 |
| M-02 | 与现网菜单对齐扩展：对话台、站点清单、文档与任务、应用配置、菜单管理、**账号管理**、**组织管理**、**角色管理** 等 |

| M-04 | 无权限路由 → 403 或回默认首页并提示 |
| M-05 | **权限粒度仅到菜单**；不做按钮/接口操作码细分（业务写接口仍须登录鉴权；管理类接口校验对应管理菜单或角色） |
| M-06 | 原前端 `localStorage` 菜单显隐**不得再作为权限来源** |

### 6.2 角色模板（本期必做）

| 编号 | 需求 |
| :--- | :--- |
| R-01 | 预置/可维护角色模板（如：普通用户、运维、管理员） |
| R-02 | 模板绑定默认菜单集合 |
| R-03 | 开户时选择模板自动勾选菜单，允许管理员再改 |

## 7. 安全与策略（除 HTTPS 外全部纳入需求）

> 部署环境为**内网**，**暂不要求 HTTPS**。以下条目均为本期需求。

| 编号 | 策略 |
| :--- | :--- |
| S-01 | 密码策略：长度 ≥ 8；须包含大小写字母与数字（符号可选）；随机密码遵守同一策略 |
| S-02 | 登录失败次数限制 + 锁定/冷却，防爆破 |
| S-03 | 密码仅经登录/改密等接口提交；服务端只存哈希 |
| S-04 | Token 过期失效；改密、停用、登出后旧 Token 立即失效（黑名单或版本号） |
| S-05 | 权限双检：前端按菜单隐藏 + **后端拒绝未授权管理操作**（防改前端绕过） |
| S-06 | 审计：登录成功/失败、开户、重置密码、改密、改权限/角色/组织、停用启用 |
| S-07 | HR 表只读；平台用户/组织/角色写操作仅限 AI 前缀表 |
| S-08 | （明确排除）不强制 HTTPS；若日后上公网再单独立项 |

## 8. 鉴权改造（用户 Token ↔ `API_AUTH_TOKEN`）

| 编号 | 需求 |
| :--- | :--- |
| T-01 | 浏览器调用业务 API 使用**用户登录 Token**（Authorization: Bearer \<user_token\>） |
| T-02 | 废除前端依赖 `.env` 中长期静态 `VITE_API_AUTH_TOKEN` 作为用户身份（开发联调可用测试账号登录，而非共用神 Token） |
| T-03 | 后端同步改造：原 `API_AUTH_TOKEN` 单密钥校验改为**校验用户 Token**（及必要的服务账号机制，若自动化脚本需要，另设 `SERVICE_TOKEN` / 机器身份，与用户登录分离） |
| T-04 | 未登录、Token 无效、强制改密未完成：业务接口返回 401/403，前端统一处理 |
| T-05 | 对话、站点、会话等现有接口一律纳入用户鉴权，并按 `staff_no` 做数据归属（如会话列表按用户隔离） |

## 11. 验收场景（用例级）

1. 未登录打开 `/chat` → 登录页。  
2. 手机号不在 `persondetail` → 开户失败。  
3. `staffStatus != IN_SERVICE` → 开户失败；在职用户可开户并必选组织。  
4. 开户随机密码 → 弹窗提示自行保存 → 首次登录强制改密 → 不改密无法进对话台。  
5. 角色模板「普通用户」仅对话台 → 侧栏无站点清单，直链 `/sites` 被拒。  
6. 勾选「今日免登录」→ 当日内重开浏览器仍保持登录；次日需重登。  
7. 停用账号或离职（登录校验非在职）→ 无法登录；旧 Token 失效。  
8. 业务 API 无用户 Token 或仅旧静态 Token → 拒绝（改造完成后）。
