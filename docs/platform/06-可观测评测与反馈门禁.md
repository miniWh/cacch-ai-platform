## 1. 定位：观测是平台能力，不是售后补丁

主流 AI 平台将下列能力视为一等公民：

| 能力 | 作用 |
| :--- | :--- |
| **Tracing** | 还原一次请求经过了哪些模型/检索/工具 |
| **Metrics** | 延迟、成功率、Token、成本 |
| **Feedback** | 用户满意度与坏例收集 |
| **Eval** | 离线回归，防止改 Prompt/模型导致质量坍塌 |
| **Release Gate** | 未过评测不得发布生产 App 配置 |

MVP 可用「结构化日志 + 表」起步；预留与 Langfuse / OpenTelemetry 对接，避免以后换埋点。

---

## 2. Tracing 最小模型

### 2.1 层级

```text
Trace (request_id, app_id, user_id)
  ├── Span: api.chat
  ├── Span: retrieve          （RAG）
  ├── Span: llm.chat_stream   （Gateway）
  ├── Span: tool.execute      （Agent）
  └── Span: persist.message
```

### 2.2 Span 通用字段

`span_id, parent_span_id, name, start_at, end_at, status, error_code, attributes_json`

### 2.3 关键 attributes（示例）

| Span | attributes |
| :--- | :--- |
| retrieve | kb_ids, top_k, hybrid, hit_doc_ids, scores |
| llm | profile_id, model, prompt_tokens, completion_tokens |
| tool | tool_id, risk_level, hitl_decision |

实现：先打日志（JSON 一行一个 span），再进专用表或外部系统。

## 3. Metrics（看板最小集）

| 指标 | 说明 |
| :--- | :--- |
| QPS / 错误率 | 按 app、capability |
| 端到端 P50/P95 延迟 | 含检索+LLM |
| 检索空结果率 | RAG 健康度 |
| Token / 成本 | 按 app、日 |
| HITL 等待时长与拒绝率 | Agent |
| 用户点踩率 | 反馈 |

告警建议：错误率突增、provider 熔断、空结果率异常、日 Token 超预算。

## 5. 离线评测

### 5.1 按能力域的评测包

| 能力域 | 核心指标 | 数据集 |
| :--- | :--- | :--- |
| RAG | 检索命中率、忠实度、应拒答率 | 黄金问答集 |
| 助手 | 指令遵循、安全拒答 | 角色场景集 |
| 生成 | 格式合规、人工偏好 | 模板样例集 |
| 文档智能 | 字段准确率 / F1 | 标注集 |
| Agent | 任务成功率、违规工具调用数 | 剧本集 |

RAG 细则仍见 [rag-agent 08](../rag-agent/08-联调评测与调优.md)；**平台要求：每域上线必须有一份基线分**。

### 5.2 实验纪律

- 一次只改一个变量（模型 / Prompt / Top-K / 混合检索开关等）  
- 记录配置哈希与得分，可回滚 App bindings / profile

## 6. 发布门禁（Release Gate）

### 6.1 建议规则

| 变更类型 | 门禁 |
| :--- | :--- |
| App 首次发布 | 过本域最小评测集；安全清单勾选 |
| 换模型 profile | 回归评测 ≥ 基线或产品书面接受降级 |
| 改系统 Prompt | 同左 |
| 开写级工具 | 必须满足 [05](./05-Agent工具安全与HITL基线.md) 上线门禁 |
| 开 ACL 强制 | 抽样账号验证「看不见不该看的文档」 |

### 6.2 状态机（App）

```text
draft → (eval pass) → published
published → (breaking change) → draft 或 canary
canary → published / rollback
```

MVP 可人工执行门禁（检查表）；P2+ 可做成发布前自动跑评测任务。
