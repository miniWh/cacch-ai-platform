## 1. 平台目标

建设可扩展的 **AI 能力平台**，统一：

- 大模型 / Embedding 接入与限流  
- 身份鉴权、审计与安全策略  
- 异步任务、配置与多环境  
- 日志、Token 成本与基础观测  

在此之上，按业务装配多种 AI 应用，而不是为每个需求从零搭一套「对话 Demo」。

### 核心闭环（平台视角）

```text
业务需求 → 选择能力域 → 复用共享底座 → 装配场景应用 → 评测与运营
```

RAG 知识问答只是其中一条闭环：**知识采集 → 检索 → 生成 → 对话交互**。

## 4. 需求归类原则（避免范围漂移）

接到「AI 需求」时，先归类再设计：

| 判断问题 | 若「是」则倾向 |
| :--- | :--- |
| 必须依据内部文档且要可溯源？ | RAG 知识问答 |
| 只要稳定多轮对话/角色，不强依赖私有库？ | 通用对话助手 |
| 需要调 API、查库、多步决策？ | Agent 编排 |
| 主要产出长文/改写/摘要？ | 内容生成 |
| 主要产出 JSON/字段/分类标签？ | 文档智能 |

**禁止**：把所有需求都写成「再做一个聊天框 + 塞进知识库」。

## 5. 非目标（平台级）

- 不在首期同时铺开全部能力域的完整实现  
- 不以单一开源 Agent 框架绑架全平台分层  
- 不把多租户计费、复杂权限作为 P0（字段预留即可）
