## 1. 为什么要有「共享底座」

平台存在多种 AI 需求时，若每个场景各自申请 Key、各自封装 SDK、各自做鉴权，会导致：

- 成本与限流无法统一治理  
- 安全策略不一致  
- 换模型要改多处  

因此：**底座建设一次，能力域只组装差异部分**。

## 3. 推荐分层（平台级）

与 RAG 工程一致，便于多能力共存：

```text
common → dao → core → {rag | agent | generation | ...} → service → manager → web
```

- `core`：仅放厂商无关的 LLM/Embedding/Prompt 基础设施  
- 各能力域目录（如 `rag/`、`agent/`）平级扩展，**禁止**域之间循环依赖  
- `manager`：按应用编排；一个应用可组合多域（例如 Agent 内调用检索工具）

---

## 4. 多能力共存时的工程建议

| 主题 | 建议 |
| :--- | :--- |
| 代码仓 | 单仓多域（`cacch-ai-platform`）或「底座服务 + 域服务」；首期可用单仓 |
| API 前缀 | `/api/v1/rag/...`、`/api/v1/chat/...`、`/api/v1/agent/...` 按域划分 |
| 数据表 | 共享 `user`/`audit`；业务表按域前缀或独立 schema |
| 前端 | 统一工作台 + 按能力挂载页面（对话、知识库、任务、生成器） |
| 配置 | 公共 Key 一份；域参数（Top-K、工具列表）分节 |
