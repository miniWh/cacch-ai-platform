# Agent 编排（规划）

> **文档状态**：📋 规划中  
> **能力归类**：工具调用、多步骤任务、流程编排  
> **依赖底座**：[平台共享基础](../platform/01-共享基础能力.md)  
> **安全前置（硬约束）**：[Agent 工具安全与 HITL 基线](../platform/05-Agent工具安全与HITL基线.md) — **实现可晚，标准现在就遵守**

## 定位

在 LLM 之上增加 **规划 → 选工具 → 执行 → 观察 → 再决策** 循环，解决「不只是回答，还要办事」的需求。

## 典型需求

- Function Calling / 工具注册（HTTP、DB、内部 RPC）  
- 多步任务与中断恢复  
- 人工确认节点（HITL）  
- 将「知识库检索」注册为工具之一（组合 RAG，而非替代平台）  

## 与 RAG 的边界

| Agent 编排 | RAG 知识问答 |
| :--- | :--- |
| 侧重大模型驱动的行动 | 侧重检索增强的回答 |
| 需要工具协议与权限沙箱 | 需要切片、向量、引用 |
| 失败重试、步骤状态机 | 召回率与忠实度评测 |

## 安全基线（摘录，全文见平台 05）

- 工具必须白名单注册，含 `risk_level` 与 JSON Schema  
- `write` / `critical` 默认 HITL；未达标不得对生产开放写工具  
- 以用户身份执行、出站域名白名单、全量审计  
- `kb_search` 必须套用 App 允许的 kb 与 [ACL 约定](../platform/04-数据面约定-ACL与对象存储.md)
